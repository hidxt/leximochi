### 结论

- ✅ **字段维度满足本项目 Phase 2 要求**：英美音标、英美发音标识、词性+释义、例句、短语/搭配、同义/反义、词形变化、真题/常考、记忆方法都有对应字段（`simple` 档只有释义+短语，必须用 `full` 档）。
- ⚠️ **必须做词形合并**：数据把同一单词拆成多行（不同词性/义项各一行），四级冗余 39.5%、六级 29.4%。已实现的导入器会在同一批次内按归一化词形合并并保留全部义项（`word-import.service.ts` 的 `mergeWords`），否则会出现重复词条、学习进度重复计算。
- ⚠️ **反义词覆盖很低**（四级 247/7508、六级 77/5651），`exam` 覆盖约 8%——不能当作「四六级常考含义」的完整来源。
- ⚠️ **没有音频文件**：`ukspeech`/`usspeech` 只是发音标识，不是可直接播放的 mp3。Phase 2 的「英美发音」需另行解决音频源（合法授权音频或 Phase 5 的 TTS），在此之前应优雅降级为只展示音标。
- ✅ 唯一词数 4,544 与公开资料中四级大纲约 4,500 词高度吻合，可作为正确性的旁证（未做人工抽检以外的逐条校验）。

## 3. 阻塞与处置

**阻塞**：该仓库及其上游均无许可证，属于「版权状态不明」的数据。按项目红线，**在获得明确授权前不得把该数据（或其衍生 JSON）提交进仓库，也不得打包进发布物**。

已完成的、不受阻塞的工作：
- 词库导入工具（`WordImportService`）：规范中间格式、事务、按词形幂等、同批次合并多行、逐条失败上报、词典数据与 AI 补充分离。8 个用例通过。

可选处置（需用户决定）：
1. **向作者取得授权**：在仓库提 issue 或邮件请求以明确许可证（如 MIT / CC-BY-4.0）并在 README 声明；拿到书面同意后即可导入，并在 `docs/asset-licenses.md` 登记来源、许可证与获取日期。
2. **改用许可证明确的数据源**（例如带 MIT/CC 许可的词表项目）——我可以先核对其许可证与字段覆盖，再实现对应转换器。
3. **只用其「词表」部分**：先向作者确认「仅词表（词形列表）」是否可单独授权；音标/释义等富字段再另找来源。注意：即便只取词表，也仍需授权或确认其不构成受保护的汇编作品。
4. 若都不成：先用自制小样本数据（方案 A）推进学习/复习链路，真实词表后续再补。

## 4. 导入器使用方式（拿到合法数据源后）

```bash
# 1) 把来源数据转换为规范中间格式（见 apps/server/src/modules/vocabulary/import/import.types.ts）
# 2) 经后台批量导入接口 POST /admin/words/import（Task 12 实现）或脚本调用 WordImportService
```

导入语义（已实现并有测试保障）：
- 整批在**单事务**内完成，失败不留半成品；
- 按 `headwordCanonical` **幂等** upsert，重复导入结果一致；
- 同批次内同一词形的多行**合并**，义项/例句/短语/词形/关系取并集并去重；
- 每次导入使 `wordbooks.version` 递增，供 Android 判断是否需要重新下载；
- 逐条返回失败原因（缺词形/空释义等），不中断整批。
